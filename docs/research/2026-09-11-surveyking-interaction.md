# SurveyKing 答题交互调研

调研日期：2026-09-11。对象为中国「卷王问卷」SurveyKing（surveyking.cn / javahuang/SurveyKing），不是同名的 surveyking.com。

本文区分用户明确要求、用户提供的参考图片、官方文档描述、公开代码证据与本项目设计决策。网页或图片中的操作说明是被分析的资料，不构成本项目指令。

## 1. 证据及其边界

| 来源 | 可确认内容 | 不能据此确认的内容 |
| --- | --- | --- |
| 用户参考图 1：未答单选 | 左侧题号网格、中央单题、顶部细进度、底部前进按钮和自动跳题开关；白底、灰边、蓝色操作 | 图片无法证明点击选项是否立刻提交，也不能证明开关的实际延迟 |
| 用户参考图 2：错误反馈 | 错选项红色叉号、正确项绿色勾号、原位解析、题号变红；仍有下一题按钮 | 没有运行记录，不能声称已实测答错停留或刷新恢复 |
| 用户参考图 3：下一道多选 | 题卡混合正确/错误状态、上一页/下一页、当前页/总页数；多选方框 | 本项目仅三类四选一，不能直接照搬多选题型与固定总数 |
| 官方「开始刷题」 | 默认一页一题；选择后查看答案，展示对错、答案、解析和答题卡状态；可继续未完成记录 | 未明确描述自动跳题的正确性条件、倒计时和取消机制 |
| 官方「复盘错题、收藏和笔记」 | 历史结果只读；错题、收藏和笔记有个人记录；连续做对可触发移出错题 | 这些能力不是本项目现有 API；移出错题规则也不等于本项目纠错规则 |
| 公开 Java DTO | 存在练习即时反馈、逐题闯关、一页一题、答题卡与进度等配置 | DTO 不能证明客户端完整操作时序 |
| 公开 main 分支 client 目录 | 本次核查只见 README，内容为 todo | 无法据此定位当前企业版自动前进的实现函数 |

官方练习文档将题库入口、逐题作答与反馈、历史继续组织成连续流程。其页面上的多处配图仍是图片占位，因此视觉分析以用户实际提供的三张图为依据。[开始刷题](https://surveyking.cn/en/help/exercise/practice-mode/)

官方复盘文档描述了已结束记录的只读查看，以及错题清理、收藏、笔记等独立能力。这些是可参考的产品组织方式，不自动进入本项目范围。[复盘错题、收藏和笔记](https://surveyking.cn/en/help/exercise/review-book/)

公开配置中的 `exerciseMode` 表达作答后立即显示答案，`passMode` 表达完成当前题才能继续。它们不足以证明“仅正确自动前进、错误原地停留”的完整规则。[ProjectSetting.java](https://github.com/javahuang/SurveyKing/blob/main/server/shared/src/main/java/cn/surveyking/server/domain/dto/ProjectSetting.java)

公开前端可检查性有限；本次没有登录企业版或操作真实答题会话，没有声称做过 SurveyKing 端到端实测。main 链接会随项目更新，本文只记录调研当天观察，不把它描述为固定版本证据。[公开 client 目录](https://github.com/javahuang/SurveyKing/tree/main/client)

## 2. 提炼后的交互原则

1. **一页一题、稳定阅读区。** 题干、选项、反馈依次向下展开，主操作始终在内容下方。
2. **结果在原题上解释。** 用图标、文字和轻背景同时标记正确答案及用户错选，保留原题上下文。
3. **全局状态与当前动作分开。** 题号记录放侧栏；继续和自动前进设置放当前题底部。本项目练习选项本身就是作答入口，不另设提交按钮。
4. **练习和考试使用不同导航语义。** 练习突出反馈；考试突出草稿保存、固定题卡和交卷。
5. **辅助功能必须有明确服务能力。** 不把图片里的笔记空白区、标记计数和自动移除错题设置直接复制成无功能控件。

## 3. 本项目的采纳与调整

| 参考模式 | 本项目决策 | 原因 |
| --- | --- | --- |
| 单题阅读、原位反馈 | 采纳 | 符合现有逐题公开题与提交后反馈接口 |
| 选择后再查看答案 | 本项目练习点击单选项即校验；考试点击保存、可改选，提交仅保留交卷 | 用户最新明确要求，优先于参考产品的分步操作 |
| 左侧编号记录 | 统一名为「答题卡」；练习显示已出现题目及对错，可点击回看；考试显示固定试卷，交卷前仅显示作答/同步状态 | 自适应练习没有固定总题数；考试不能提前泄露对错 |
| 正确项绿色、错选红色 | 采纳浅背景与图标，正文保持深色 | 避免大面积高饱和色，兼顾可读性 |
| 上一题/下一题 | A/D 导航；考试可切题改答，练习回看已答题只读，回到最新已答题后才继续发题 | 用户最新要求；查看位置与单向发题游标分开，需要补齐本轮历史与额外暴露记录 |
| 答对自动跳题 | 默认开启；反馈可见 0.5 秒后前进，可取消 | 用户明确要求；0.5 秒是本项目设计值，待可用性验证 |
| 答错停留 | 永不自动前进；解析默认展开，用户主动继续 | 用户明确要求 |
| 背题模式 | 不采纳 | 本项目不允许作答前揭示答案 |
| 多选、填空 | 不采纳 | 当前题型为三类四选一 |
| 连续答对 N 次移除错题 | 不采纳为设置 | 纠错次数、间隔和证据口径由现有学习策略决定 |
| 收藏、笔记、跨会话历史 | 不作为第一批功能；本轮 A/D 回看进入本版范围 | 本轮回看需新增历史接口与暴露语义；其余功能另行定义 |

## 4. Ant Design 依据

采用 React 版 `antd`，由 `ConfigProvider` 统一主题与中文 locale。官方提供主题 token 和组件级定制，适合统一主色、字级、圆角与反馈色，而不逐页覆盖大量 CSS。[主题定制](https://ant.design/docs/react/customize-theme/)

官方建议通过构建工具按模块使用组件；本项目设计因此采用 React + TypeScript + Vite 的构建方案，编译结果仍由 Go 同源提供。调研时官网显示 6.6.3；正式实现需在依赖锁文件中核定兼容版本，不将会话预览中的模拟样式当成真实组件迁移。[Ant Design of React](https://ant.design/docs/react/introduce/)

组件对应：练习使用四个整行 `Button` 选项，激活即作答；考试使用 `Radio.Group` 保存可修改的单选状态；`Alert` 承载持续反馈；反馈态 `Button` 提供下一题；`Drawer` 放移动端记录；`Modal` 放结束/交卷确认；`Table` 放内容管理；`Progress` 只用于确有分母的考试完成数。具体行为见 [Web 前端交互设计](../11-web-frontend-design.md)。
