# 题库与内容生产

## 1. 用户输入

首版推荐支持：从基础词库选词、粘贴一行一个词、导入简单词表文件。输入包含题库名称、词条范围，可选指定词义和用途备注。

Go 保留 raw_input，执行规范化、去重、词条匹配和目标词义解析。不要把 LLM 输出的单词、词性、词义或频率当作天然标准数据。

多义词不自动等于异常。如果基础词库为 CET-6 定义了明确的目标词义集合，可按带版本的课程规则自动纳入，并在导入结果中列出采用的词义。用户指定义、来源冲突、无法匹配和疑似拼写错误进入异常队列。

import_item 状态建议：resolved、ambiguous、not_found、invalid。每次解析保存候选和采用理由；人工处置不属于学习者自评，它是在确定学习内容。

基础词库来源尚未选定。词频、六级重要度、真题出现次数必须各自标识来源和统计口径；缺失保持缺失，不让模型填造数值。

标准数据源通过来源登记及条目导入接口建立；普通建库词表只引用已有 source_id/source_version 和词义解析策略。来源清单至少包含名称、定位信息、版本、可用范围说明、词条外部 ID、释义与统计口径。没有这类元数据的用户裸词表仅表示目标词范围，不冒充词义来源。

## 2. 每个生成任务的输入契约

```text
job_id / item_id / bank_id
lexeme_id / sense_id / sense_version_id
canonical_form / part_of_speech / target_meaning
source_entry_refs / curriculum_policy_version
required_task_families / requested_form_counts
generation_config_version / quality_policy_version
```

数量和题型配置由系统提供默认值；不要求用户理解提示词或 LangGraph。每种题型至少有一个合格形式才可测试；有两个合格形式才具备同题型换题纠错的条件。不为凑数发布失败题目。

## 3. 生产分工

| 类型 | 方式 | 主要检查 |
| --- | --- | --- |
| 词义识别 | 标准词义 + 固定模板 + 干扰释义候选 | 其他选项不是该英文词的另一个有效答案；词义范围明确 |
| 反向选择 | 标准释义 + 固定模板 + 英文干扰词 | 近义词不能使两个选项都合理；词性与提示一致 |
| 语境选择 | 模型生成语境、空缺与候选 | 自然度、搭配、时态词形、目标义、唯一合理答案 |

干扰词可以来自基础词库，但整套选项必须一起检查。在线个性化选择已发布的完整组合，不在线混装未检查过的选项。

## 4. LangGraph 工作流

```text
领取固定输入任务
  → 校验词义与来源
  → 按词义并行生成候选
  → 结构与业务规则校验
  → 语义评估
      ├─ 通过 → Go 幂等接收并发布
      ├─ 可修正 → 带反馈重新生成，受重试/成本上限约束
      └─ 无法判定、来源缺失或次数用尽 → 异常待处理
```

LangGraph 的分发、条件分支、持久化和暂停恢复用于编排。业务词义身份、内容审计和正式发布由 Go 持有。LangChain 的结构化输出不代替语义验证。[S05](06-sources.md)、[S06](06-sources.md)

网络/限流重试与语义修订是两种计数；所有循环有终止条件。节点恢复可能重执行副作用，因此候选接收、质检入账和发布都按逻辑 item/attempt identity 去重。

生成租约过期后可重新领取；旧 worker 的迟到结果须经租约和输入版本校验。checkpoints.db 是运行状态，不是唯一审计来源。

## 5. 候选与版本留痕

每次有效生成保存 question_candidate：

- 结构化候选正文、目标输入引用、模型标识、prompt/config 版本。
- rule_check_result、semantic_check_result、检查器版本和问题理由。
- 本次尝试编号、父候选、修订关系、消耗统计（可获得时）。
- 最终处置：发布、拒绝、待处理、被后续候选替代。

已发布题目永久保留其必要来源链和检查依据。失败候选正文的保留期可以配置；清理后仍保留摘要、处置及关联 ID。没有必要把保存所有供应商传输载荷作为首版要求。

相同输入/模型不保证再次生成相同内容；重放学习状态使用原题目版本，不重新调用模型“恢复”历史题目。

## 6. 自动发布与异常处理

程序门槛包括：目标存在、字段类型正确、四个非重复选项、一个答案键、词形规则合法、目标版本一致、去重通过。语义门槛包括：符合来源词义、无已检测多解、语境自然、解析与答案一致。

自动通过是质量策略的结果，记录 `auto_passed`，不写成 `human_verified`。模型给出的自评高分不能单独决定通过。评估器无结论或互相冲突时进入异常流程。

异常允许修订、排除或重新生成。人工修订也须重新跑结构规则，语义检查与处理依据分别保存。

发布后发现错误：停用版本 → 关联受影响实例/作答 → 创建修订版本 → 明确决定旧评分/证据处置。普通措辞改善不自动使历史答题无效；错答案或多解才进入评分/证据修正流程。

## 7. 自动检查的验证

准备覆盖错义、多解、近义重叠、错误词形、无解句子、解析冲突、重复形式的检查样例。分别报告漏检和误拦截。先用可核验的小批词表检查流程，再批量扩充；“第二个模型说没问题”不等于已证明唯一答案。
