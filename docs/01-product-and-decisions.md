# 产品范围与决策记录

状态：冻结规格 1.1.0，2026-09-08。P01–P13 为产品边界；E01–E13 为已冻结的工程起点，效果未验证。最终约束与审查处置见 [00](00-frozen-design.md)，数值见 [policy-v2](../config/policy-v2.json)。

## 1. 系统目标

用户负责作答，系统记录客观表现，并决定当前题库中下一题的目标词、测试任务和题目形式。用户可以自主开始或结束练习，也可以按条件组卷考试。

系统不要求用户选择“认识、模糊、不认识”，也不要求设置考试日期、每天学习时间或每日新词量。

## 2. 已确认决策

| ID | 决策 | 影响 |
| --- | --- | --- |
| P01 | 独立 Go 后端，SurveyKing 只参考 | 不依赖 Java 服务、共享数据库或现有前端协议 |
| P02 | 个人使用，不做用户隔离 | 所有题库共用一个学习档案；首版没有账户、权限和协作模块 |
| P03 | 题库驱动的练习和考试 | due_at 是选题依据，不是每日待办任务 |
| P04 | 词义识别、反向选择、语境选择三种四选一 | 不测试主动英文输入、拼写和听音 |
| P05 | 练习由系统自动选择词与题型 | 用户只需选择题库，候选目标词限定在该题库 |
| P06 | 同一词义、同一任务跨题库共享学习状态 | `(sense_id, task_family)` 是单人学习单元，题库不是记忆状态主键 |
| P07 | 不允许作答前查看答案 | 提交有效选项后才返回训练反馈；未提交或退出不记成答错 |
| P08 | 训练即时反馈并穿插纠错 | 纠错作答记录反馈条件，与延迟观测分开解释 |
| P09 | 考试预先固定实例、统一提交评分 | 考试中不自适应改卷，不提前反馈 |
| P10 | 一张试卷内同一标准单词只作为目标词出现一次 | 不通过切换词义或题型绕过去重；不足时提示调整条件 |
| P11 | 考试数据进入学习记录 | 考试评分和记忆观测的解释规则分离 |
| P12 | LangGraph 离线生成题库 | 在线判题、更新状态、选下一题不调用 LLM |
| P13 | 合格内容自动可用，异常人工处理 | 发布门槛版本化，不要求逐题人工审核 |

建库输入已选定为基础词库选词、粘贴词表和UTF-8 TXT/CSV导入；普通匹配自动处理，来源冲突和无法匹配项进入异常队列。

## 3. 任务名称和报告含义

| task_family | 输入与作答 | 可以报告的含义 |
| --- | --- | --- |
| `meaning_recognition` | 英文 → 选择中文词义 | 给定候选中的词义识别表现 |
| `reverse_selection` | 中文词义 → 选择英文 | 给定候选中的反向辨认表现 |
| `context_selection` | 语境空缺 → 选择英文 | 给定句子和选项下的语境判断表现 |

内部使用 task_family，避免暗示已经测量潜在通用能力。报告保留样本数与观测条件；不能把反向选择标成主动回忆，也不能把语境选择标成写作使用能力。未测任务显示证据不足。

## 4. 已冻结工程决策

| ID | 决策 | 状态与理由 |
| --- | --- | --- |
| E01 | Go 模块化单体 + SQLite；Python 独立 worker | 适合单机个人版，降低部署依赖 |
| E02 | Go 业务库与 LangGraph 检查点使用不同文件 | 避免共享写锁，区分业务审计与运行恢复 |
| E03 | FSRS-6 + Good/Again 作为间隔基线 | 有 Go 实现；选择题上的效果仍需验证 |
| E04 | 表现、记忆、混淆使用不同逻辑投影 | 从同一事实派生，独立更换统计与调度算法 |
| E05 | 干扰项可来自基础词库，目标词仍限当前题库 | 小题库也能组成合理选项；组合必须质检 |
| E06 | 个人版最多一个未结束作答会话 | 允许关闭页面后恢复；切换前结束或放弃，避免考试延迟交卷造成模型事件乱序 |
| E07 | 首版改答考试题只进入表现证据，不立即更新 FSRS | 保留完整时间线；作为保守候选策略，见学习文档中的局限 |
| E08 | 每次有效纠错提交各进入 FSRS 一次，使用实际时间及同日分支 | 网络重试不再计入，队列本身不增加记忆强度；效果待对照验证 |
| E09 | 普通题 sibling 间隔 5 个其他单词，纠错间隔 3 个 | 是可配置工程起点，不是实证阈值；小题库有明确处理 |
| E10 | 每学习单元每会话最多 2 次纠错重试 | 避免密集循环；结束本轮不代表长期掌握 |
| E11 | 普通题每 4 个位置为未测内容预留 1 个 | 防止只练到期/薄弱内容；候选不足互补 |
| E12 | Go 模板 + 原生 ES modules/CSS，同源、无 Node 构建链 | 冻结首版界面交付方式 |
| E13 | 原创 fixture 先行，ECDICT 仅作版本化候选来源 | 汇编释义不直接成为标准 sense；生产源必须通过导入门槛 |

E07 不认定改答必然反映记忆失败，也不认定首次点击是首次独立提取；它保留不确定性。是否更换为“最终答案单次更新”需用数据比较，不在代码中永久写死。

## 5. 本轮审查采纳方式

- 采纳：证据层与 FSRS 分开、观测规则版本化、首次与最终答案分离、候选及来源留痕、运行库版本固定、状态可重建。
- 修正：首次点击只是一条可观察行为；“独立”只能表示满足系统内可检查的条件。
- 修正：观测属性可重叠，不压缩为一个互斥枚举；证据解释从原始事实派生。
- 修正：个人题目正确率不等于题目难度；混淆统计同时保存选项出现机会和被错选次数。
- 修正：不同 question_version 不必然代表不同题目形式；纠错要优先更换实质内容。
- 修正：多义词不必一律人工消歧。基础词库有明确目标词义策略时可自动纳入，保留来源和规则。
- 限定：统计投影不宣称是经过校准的能力预测模型；候选历史保存不等于无限保存所有供应商返回数据。

## 6. 暂不纳入首版

多用户、题库分享、班级、公开部署权限、每日计划、主动输入、听力题、在线 LLM 判题/选题、复杂 IRT/BKT 训练、文档自动提词、通用问卷设计器。
